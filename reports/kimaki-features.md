# Kimaki User-Facing Feature Inventory

Inventory of kimaki's user-facing features that must be ported or mapped to omomaki. Sources: `_refs/kimaki/README.md`, `_refs/kimaki/AGENTS.md`, and feature source files under `_refs/kimaki/cli/src/`.

## How messages reach a session (README summary)

From README, "How messages reach a session": when you send a message during an active run, OpenCode normally queues it to run **after the current tool call**. Kimaki adds an interrupt: if the current step is still going after ~3 seconds, Kimaki **aborts it and force-sends your message**, then resumes. So a message acts as an interrupt instead of waiting forever behind a long-running command. Implemented in `cli/src/opencode-interrupt-plugin.ts` (`session.abort` then `session.promptAsync` replay, see AGENTS.md "aborting and resuming opencode session").

## Porting/mapping notes

- The 3s interrupt, local queue state, and btw fork all live at the session-runtime layer (`thread-session-runtime.ts` + plugins that run inside the OpenCode server process), not in Discord handlers — port these together.
- `. queue` and `. btw` suffixes share the same regex pattern (`QUEUE_SUFFIX_RE` in `message-preprocessing.ts`, `BTW_SUFFIX_RE` in `btw-prefix-detection.ts`); both are extracted from raw message content before file attachments are appended.
- Queue/btw/worktrees interact: btw forks copy the session model and respect worktree directories; agent quick commands can auto-create worktrees.
- AGENTS.md architecture map: `cli/src/cli.ts` (main CLI, onboarding wizard), `cli/src/discord-bot.ts` (event loop, session routing), SQLite at `~/.kimaki/discord-sessions.db` for local state.
